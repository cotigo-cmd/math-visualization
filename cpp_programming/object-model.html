CPP-02

对象内存模型：构造、析构与 this

教材§8.3.4 · §9.1 · §9.5.3 · §11.5 · §11.6 · §12.3 · §12.4 · 图 CPP-02 · 五个交互实验

定义一个类，编译器就在内存里给对象排了一张「字节座位表」；调用成员函数时，又悄悄多传了一个参数 this；继承与虚函数再在这张表前面加了一个看不见的指针。这一页画的，就是对象在内存里的真实样子——为什么 sizeof(Time) 是 12、为什么同一个函数能服务十个对象、为什么基类析构函数最好加 virtual。

用类定义对象时，系统只为数据成员分配空间。教材原话：sizeof(Time) 在 Visual C++ 下输出 12，证明「一个对象所占的空间大小只取决于该对象中数据成员所占的空间，而与成员函数无关」。所以一个类定义 10 个对象，不会存 10 份相同的函数代码，而是共用一段目标代码。

图 CPP-02a · 一块对象内存的实况（每格 4 字节）切换成员组合，看偏移与总字节

布局规则（以本页模型为准，64 位典型值）：每个成员放在「自身对齐的整数倍」偏移上，中间不足的部分是填充；整个对象的总大小还要补齐到最大成员对齐的倍数（否则对象数组里第二个元素会错位）。char 对齐 1、int 对齐 4、double 对齐 8。

class Time { // §8.3.4 的例类
public:
 int hour; // · 4 字节
 int minute; // · 4 字节
 int sec; // · 4 字节
 void set(); // 目标代码在对象外：sizeof(Time) == 12
};
Time t1, t2; // 两个对象，两段数据，一段函数代码

推论「类里加了函数，对象会变大吗？」——不会。inline 也一样：inline 决定调用点是「插入代码拷贝」还是「跳转到入口地址」，与成员函数是否占用对象空间不属于同一范畴（§8.3.4 说明 2，教材特别提醒别把两者搞混）。

S 02this 指针：一段代码，十个对象

§9.5.3：成员函数藏着一个隐式形参 Box* this，调用 a.volume() 时编译系统把 &a 传进去。

十个对象共用一段 volume 代码，怎么知道该算谁的数据？教材的解释：C++ 设立了一个名为 this 的指针，调用 a.volume 时指向 a，调用 b.volume 时指向 b。函数体里的 height 其实是 this->height——成员访问默认经过 this。下面点一个对象，看这段公共代码的 this 滑向谁。

图 CPP-02b · 同一段 volume 代码，三个候选对象点对象切换 this 的指向

教材把编译后的实际形式写了出来：int Box::volume(Box *this)，调用写成 a.volume(&a)。「这些都是编译系统自动实现的，编程序者不必人为地在形参中增加 this 指针」。需要时也可以显式写：this->height，或用 *this 表示「本对象」——注意 *this 两侧括号不能省，*this.height 会被解析成 *(this.height)。

推论静态成员函数没有 this 指针（§9.6）：它不属于任一对象，因此无法访问非静态成员——想访问就得显式传对象进来。上面的 static count() 按钮演示的正是这一点：计数能走，读 this->height 无从谈起。

S 03构造与析构的时序：先基类，后派生

§11.5：构造时①先调用基类构造函数，②再执行派生类构造函数本身；析构严格倒序。

派生类对象建立时执行构造的顺序是：①派生类构造函数先调用基类构造函数；②再执行派生类构造函数本身。教材用 Student1 : Student(n, nam, s) 的初始化表实现第一步——基类成员的初始化必须借道初始化表，构造函数体里只能给派生类自己的成员赋值（那时基类部分已经建好了）。析构则完全相反：先执行派生类析构函数 ~Student1()，再执行基类析构函数 ~Student()。

图 CPP-02c · 一次「构造 → 析构」的完整时序先构造，再析构
class Student { // 基类
public:
 Student(int n, string nam, char s) // 基类构造函数
 : num(n), name(nam), sex(s) {}
 ~Student() { /* ... */ }
private:
 int num; string name; char sex;
};
class Student1 : public Student { // 公用派生类
public:
 Student1(int n, string nam, char s, int a, string ad)
 : Student(n, nam, s), age(a), addr(ad) {} // ① 先造基类部分
 ~Student1() { /* ... */ } // 析构按 ~Student1 → ~Student 倒序
private:
 int age; string addr; // ② 再造派生类新增部分
};

顺序反了会怎样析构顺序倒过来是有道理的：派生类的析构函数体可能还在访问基类成员（比如基类提供的 ofstream），如果基类先被拆了，派生类清理时读到的就是已析构对象。构造同理——基类部分没建好之前，派生类构造函数体碰它也是未定义行为。

基类与派生类对象之间有赋值兼容关系：派生类包含基类的成员，所以 al = bl;（A al; B bl;，B 公用派生自 A）合法。但教材图 11.26 说得很直白：赋值时「派生类新增的部分舍弃不用」。所谓赋值只是对数据成员赋值，对成员函数不存在赋值问题；赋值后也不能通过 al 去访问 bl 的派生成员（al.age 直接编译错误）。子类型关系是单向、不可逆的。

图 CPP-02d · al = bl 到底拷走了哪些字节先看布局，再执行赋值

四种合法形态（§11.6）：派生类对象 → 基类对象赋值；派生类对象 → 基类引用赋值/初始化；函数形参是基类对象/引用，实参传派生类对象；派生类对象地址 → 基类指针。注意引用那一条：A& r = bl; 之后 r 不是 bl 的别名，它只是 bl 中基类部分的别名，与 bl 有相同的起始地址。若基类有虚函数，al 的 vptr 也会被改写成基类的版本（见下一节），多态行为随之丢失。

S 05虚函数表与虚析构函数

§12.3.3：类带虚函数时编译系统构造一个 vtable——指针数组，存每个虚函数的入口地址；调用走动态关联。

通过基类指针调用虚函数时，编译期无法确定调用哪个类的函数（pt->display() 里 pt 指向谁要到运行期才知道），于是关联被推迟到运行阶段——动态关联（滞后关联）。实现的抓手就是 vtable：每个带虚函数的类有一张指针数组，对象里则藏着一个指向它的指针（vptr）。pt->display() 实际是「按 pt 找到对象的 vptr → 找到该类的 vtable → 取 display 槽位的入口地址 → 调用」。

图 CPP-02e · 基类指针 p 依次指向三个对象切换指向，再切 virtual 开关对比

把 virtual 开关关掉再点 p->display()：静态关联下编译期就按指针的静态类型（Point*）确定调用 Point::display——三次调用输出同一份内容。打开后，同一句代码对三个对象给出三种行为，这就是多态。

class Point {
public:
 virtual void display() const; // 虚函数：进 vtable
 virtual float area() const { return 0; }
 virtual ~Point() {} // 虚析构：基类析构最好都加
};
class Circle : public Point { // 派生类自动重写 display / area
 void display() const; // 不写 virtual 也自动是虚函数
 float area() const { return 3.14f * r * r; }
 int r;
};
Point* p = new Circle;
p->display(); // 动态关联 → Circle::display
delete p; // ~Point 为虚 → ~Circle 先执行，再 ~Point

虚析构教材例 12.3 的执行对照：Point* p = new Circle; delete p;——基类析构非虚时只输出 executing Point destructor，派生类的 ~Circle() 根本不执行（泄漏派生部分）；把 ~Point 改成 virtual 后输出两句，先 ~Circle 再 ~Point。基类析构一旦为虚，所有派生类析构自动成虚。反之，构造函数不能声明为虚函数——对象还没建好，谈不上绑定。

什么函数该声明 virtual（§12.3.3 的四条判据）：① 所在类会作为基类，且派生后可能改功能；② 功能不会变、派生类用不到的，别虚；③ 会被基类指针/引用调用的，该虚；④ 基类中只预留名字的，可以写成纯虚函数 virtual float area() const = 0;——带纯虚函数的类是抽象类，不能定义对象，只当接口用（§12.4）。
