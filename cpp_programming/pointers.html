CPP-01

指针：地址、解引用与所有权

教材§6（6.1–6.3 · 6.7 · 6.10 · 6.11）· 图 CPP-01 · 五个交互实验

指针难，不是因为语法怪，而是因为它把平时看不见的东西搬到了前台：内存是一排带编号的格子。变量是给格子起的名字，指针是存着格子编号的变量。下面每一节都给出一个可以拨动的实验；看数字比看文字快。

S 01内存、地址与解引用

把 & 和 * 看成一对互逆操作：取编号、按编号访问。

编译器把每个变量安排到一个编号上，这个编号就叫地址。运行时刻指针里存的既不是 42 也不是 "a"，而是一个整数编号。&a 取出 a 的编号，*p 表示「去 p 里记的那个编号，按 int 读出 4 个字节」。

图 CPP-01a · 一块栈内存的实况用下方按钮移动 p 的指向

指针自己也是变量，也占一格内存（0x00007ffd1014 那一格就是 p）。这就是「二级指针」int** pp = &p 存在的理由：想改 p 本身，就得拿到 p 的地址。

要点指针的大小与所指类型无关。在 64 位平台上 sizeof(int*) == sizeof(double*) == sizeof(char*) == 8，因为三者存的都是同一个编号。变的只是解引用时读几个字节，以及 p+1 走多远。

下面这段代码对应上图（a、b、c 相邻排列是编译器的常见安排，标准并不保证顺序）：

int a = 42, b = 17, c = -3;
int* p = &a; // p 里存的是 a 的地址
std::cout << p; // 0x00007ffd1000 —— 一个整数编号
std::cout << *p; // 42 —— 按编号回去读 4 个字节
*p = 99; // 改的是 a 本身，不是 p
p = &b; // p 改指向；a 仍是 99
p = nullptr; // 空指针：合法状态，但 *p 是 UB（多数平台段错误）

S 02p+1 到底加了几个字节

指针算术的单位是「元素」，不是「字节」。这正是数组与指针能互通的根基。

教材 §6.10.2 的原话：p+i 代表地址 p + i*d，d 是 p 所指变量占用的字节数。所以同一句 p+1，int* 走 4 字节，char* 走 1 字节，double* 走 8 字节。

i =

因为 a[i] 被定义为 *(a+i)，所以下标运算本身就是一次指针加法再解引用。&a[i] == a + i。数组名在大多数表达式里退化成首元素地址——但 sizeof(a) 是例外，它给出整个数组的字节数（只有在定义 a 的那个作用域里才成立；传进函数后就退化成了指针）。

越界p+5 算地址不违规，*(p+5) 才是未定义行为。标准只允许指针指向「数组最后一个元素的下一个位置」（即 a+5 这种尾后指针，可比较、不可解引用）。滑杆拨到 −1 或 5 以上时，上面的格子会标红——那不是「读到别的变量」这么简单，是任何事都可能发生：读到垃圾、被优化掉、程序崩溃。

S 03按值、按指针、按引用传参

同一条 swap 逻辑，三种写法，三种结局。点三次按钮看完一次完整调用。

规则只有一条：实参到形参永远是拷贝。值传给的是「3」这个数，指针传给的是「编号」，引用不传，只是给实参起了第二个名字。所以「传指针能改外面」并不是指针的特权，而是因为拷贝到的是地址，顺着地址能摸回原变量。

① void swap(int a, int b) — 按值
② void swap(int* px, int* py) — 按指针
③ void swap(int& rx, int& ry) — 按引用

推论：想在函数里改调用方的指针本身（而不只是它所指的对象），必须传 int** 或 int*&。这是「用指针作函数参数」最容易翻车的地方。

void alloc(int* p){ p = new int[10]; } // 改的是形参副本，外面 p 仍是 nullptr —— 泄漏 + 无效
void alloc(int** pp){ *pp = new int[10]; } // 顺着 pp 改到外面的 p（§6.7 二级指针）
void alloc(int*& p){ p = new int[10]; } // 引用版，C++ 里更常用（§6.11）
对比项指针 int*引用 int&
能否为空能，nullptr 是合法值不能，必须绑定到一个对象
能否改绑能，随时指向别处不能，一生只绑一个对象
是否必须初始化不必（但未初始化的指针是定时炸弹）必须
占用内存占，一个地址（8 字节）概念上不占，实现上通常就是个指针
多级int** 合法无「引用的引用」（int&& 是右值引用，另一回事）
典型用途可选的输出参数、数组、动态内存、多态函数形参、运算符重载、避免拷贝

S 04const 与指针的四种组合

只在两个位置放 const，却有四种含义。点一行，试两个操作。

读法：const 修饰它左边最近的东西；若 const 在最左边，则修饰它右边。等价关系：const int* p ≡ int const* p。所以真正要分清的是两件事——能不能改 *p（所指对象）与能不能改 p（指向本身）。

为什么值得记函数参数里 const int* 是最常见的写法，语义是「我只读，不改你的数据」。它还能让 const 对象传进来：int* 形参接不了 const int 实参，const int* 可以。反过来，const 是编译期承诺，用 const_cast 强行去掉后修改真正 const 的对象是未定义行为（常量可能放在只读段）。

S 05栈与堆：悬垂、泄漏、所有权

指针最大的杀伤力不在语法，而在生命周期。逐个动作试一遍。

局部变量住在栈上，函数返回就自动消失；new 出来的对象住在堆上，只有 delete 才会消失。delete 只是把堆块还给分配器，它不会改你的指针——指针仍记着那个编号，于是变成悬垂指针（dangling pointer）。

三条铁律（违反任意一条都是 UB，且往往在别处才崩）：

规则为什么
delete 后立刻置 nullptr把「已失效」变成「可检测的空」，第二次 delete 空指针是合法的空操作
一个块只 delete 一次二次释放会破坏分配器的空闲链表（double free），常被攻击者利用
new[] 配 delete[]new int[10] 用 delete 释放是 UB；数组版需要知道析构多少个元素

现代 C++ 的正解是让所有权由对象类型表达，让析构函数替你 delete（RAII）：std::unique_ptr<int> p = std::make_unique<int>(7);——离开作用域自动释放，拷贝被禁止，编译期就堵住了二次释放与泄漏。

S 06速查与常见错误

考前十分钟看这一节。

写法含义
&x取 x 的地址（类型 int*）
*p解引用：按 p 中的地址访问对象（左值，可读可写）
p->m等价 (*p).m
a[i]等价 *(a+i)；对指针同样成立
p + i地址加 i*sizeof(*p) 字节
p - q两指针相减得 ptrdiff_t：相隔多少个元素（须同数组）
p == q比较的是地址，不是所指内容
nullptr空指针常量（C++11）；NULL 是宏，可能是 0，有重载歧义风险

八个高频错误

1. 定义指针不初始化，直接 *p（野指针）　2. delete 后继续用（悬垂）　3. 同一块 delete 两次（double free）　4. new[] 配 delete　5. 函数里 return &local;（返回栈地址，返回即失效）　6. 数组越界写，踩坏相邻变量　7. 在函数内改指针形参，指望改到调用方（要 int** / int*&）　8. 用 == 比较两个字符串指针（比的是地址，不是内容；要 strcmp）

调试遇到崩溃先问三件事：这个指针是 nullptr 吗？它指向的块还活着吗？（-fsanitize=address 能抓住 use-after-free / 泄漏 / 越界，比肉眼找快一个数量级。）
