递归调用栈：阶乘、汉诺塔与栈溢出

谭浩强《C++ 程序设计》第 4 章 §4.6 · §4.7 · §4.12 · 习题 9 · 图 CPP-03 · 五个交互实验

递归难，不是因为公式怪，而是因为同一个函数同时活着很多份。每次调用都往栈上压一帧，每帧里有自己的形参和局部变量；返回时帧弹出，值自底向上回填。这一页把压入与弹出画出来：阶乘看两阶段，汉诺塔看递归树与栈深，最后一节看栈是怎么被压爆的。

S 01一次函数调用发生了什么

教材 §4.7 图 4.10：调用不是「跳过去」这么简单——要记返回地址、保护现场，才能活着回来。

教材把一次调用拆成五步（图 4.10）：① 执行调用前的语句；② 流程转到被调用函数入口，同时进行参数传递，并记下当时执行指令的地址、「保护现场」；③ 执行函数体；④ 流程返回先前记下的地址处，把返回值带回、「恢复现场」；⑤ 继续执行未完成的语句。这些「记下来」的信息，就住在接下来每一张图里的栈帧中。

图 CPP-03a · y = fac(3) 的五步（逐步播放）点「下一步」逐程推进

这就是 §4.7 讲内置函数（inline）的动机：调用有真实的时间和空间开销，把函数体直接嵌入调用点可以省掉②④两步。但教材同时提醒：「包含循环语句和 switch 语句的函数或一个递归函数是无法进行代码置换的」——递归函数每次调用都要有自己的一帧，编译期展开不了，编译器会忽略 inline 声明按普通函数处理。

为什么值得记返回地址是递归能回来的原因。没有它，函数返回时不知道该回到哪一行。递归函数看上去「调用了自己」，实际上每次调用的返回地址各不相同：fac(3) 里调用 fac(2) 的返回地址指向 f = fac(n-1) * n 这一行，而不是 main 里的调用行。

S 02阶乘：栈帧的压入与弹出

例 4.6（§4.6）。递归分成两阶段：回溯把问题一层层分解下去，递推把值一层层算回来。

教材例 4.6 的递归函数（返回类型用 long，因为阶乘长得快）：

long fac(int n)
{
    long f;
    if (n < 0)        { cout << "n<0,data error!" << endl; f = -1; }
    else if (n == 0 || n == 1) f = 1;        // 边界条件：到此为止，不再调用自己
    else               f = fac(n - 1) * n;   // 递归调用：先拿到 fac(n-1)，再乘 n
    return f;
}

关键在于：fac(n-1) 没返回之前，乘法做不了。所以 fac(5) 必须先把 fac(4) 压栈，fac(4) 再压 fac(3)……直到 fac(1) 撞上边界条件。这一路向下的过程就是教材图 4.8 说的回溯（问题分解，值还全不知道）；随后 1 → 2 → 6 → 24 → 120 逐层返回，就是递推。每层都有自己的 n 和 f——它们是同一段代码的不同实例。

把进度走完，读三个数：调用次数 = n（fac(n)…fac(1) 各一次）、返回次数 = n、乘法次数 = n−1。事件时间线上前半段全是青点、后半段全是琥珀点——线性递归的两阶段在时间轴上干净地分成两半，这是它和树形递归（下一节汉诺塔）最直观的区别。

地址每一层的帧地址都不同：第 d 层帧的起始地址 = 基址 −(d−1)×32。教材 §4.12.1 原话：「在函数调用开始时分配动态存储空间，函数调用结束时释放这些空间……两次分配给此函数中局部变量的存储空间地址可能是不相同的。」上面每帧左侧的琥珀色地址就是按这个模型画的（基址为示意值）。

S 03年龄：回溯与递推两阶段

例 4.5（§4.6）。复现教材图 4.8：5 个人问年龄，回溯到第 1 个人后一路递推回来。

「第 5 个人比第 4 个人大两岁……第 1 个人 10 岁」，写成递归公式就是 age(1) = 10、age(n) = age(n−1) + 2。教材图 4.8 把求解分成两阶段：回溯——把第 n 个人的年龄表示为第 n−1 个人的函数，一直回溯到 age(1) 已知；递推——从 10 岁推出 12、14、16、18。

int age(int n)
{
    int c;
    if (n == 1) c = 10;              // 边界条件：第 1 个人 10 岁
    else       c = age(n - 1) + 2;   // 回溯：先问前一个人
    return c;
}

走完后对一眼公式：age(n) = 10 + 2(n−1) = 2n + 8。age(5) = 18，与教材运行结果一致。递归在这里并不比循环快——它胜在「只写递归公式和边界条件就能把问题讲清楚」，这正是 §4.6 末尾说的：实现递归时间空间开销大，但符合人的思路，可读性优先。

易错把两阶段的顺序搞反。不是「先算 age(5) 再往下」——age(5) 的值在 age(1) 返回之前始终不存在。任何在递归调用之前就使用返回值的写法（如 c = 2 + age(n-1) 写成先自增再判断边界）都会算错。弹栈时值是自底向上回填的，这一点看上面的动画比看文字快。

S 04汉诺塔：递归树与栈深同步

第 4 章习题 9。3 个盘子 7 步、4 个 15 步、n 个 2n−1 步——边看塔边看栈。

习题 9：A 座上有若干个盘子，大的在下小的在上，每次只许移一个盘、3 座上始终保持大盘在下，借助 B 座全部移到 C 座，打印移动步骤。递归写法只要三行（教材未附参考程序，此处按递归公式给出）：把「移 n 个盘」拆成「移上面 n−1 个到中转座 → 移最大的盘 → 把 n−1 个从周转到目标」。

void hanoi(int n, char a, char b, char c)   // 把 n 个盘从 a 移到 c，b 是中转座
{
    if (n == 1) { cout << a << "→" << c << endl; return; }  // 边界：只有一个盘，直接搬
    hanoi(n - 1, a, c, b);                   // ① 上面 n-1 个盘：a → b
    cout << a << "→" << c << endl;       // ② 最大的盘：a → c
    hanoi(n - 1, b, a, c);                   // ③ b 上的 n-1 个盘：b → c
}

三个值得盯的数：移动步数 = 2n−1（每一步都打印一次，与调用次数相同）；hanoi 帧的最大栈深 = n（算上 main 帧是 n+1）；hanoi 的总调用次数也 = 2n−1。注意时间线上青点和琥珀点是交替出现的——树形递归的回溯与递推交织在一起，和上一节阶乘的「先全下钻、再全返回」完全不同。

64 个盘子教材说老和尚要移 64 个盘：步数是 264−1 = 18 446 744 073 709 551 615。按每年 365 天、每秒移一步估算约 5849 亿年——递归公式三行就够，代价全在指数上。另一个代价在栈上：n 个盘需要 n 层 hanoi 帧，这个倒是线性的，64 层毫无压力；压爆栈的是那些每层都派生出深层调用的写法（见下一节）。

S 05栈溢出与 static 陷阱

§4.12.1–4.12.3。帧只进不出会怎样；static 局部变量为什么「不跟着调用走」。

每一层递归都要一帧，而栈的容量是有限的（Linux 默认常见 8 MiB，ulimit -s 可查；Windows 默认通常 1 MiB）。少了边界条件，或边界条件永远够不着，帧就只进不出——直到 栈溢出：Linux 上进程收到 SIGSEGV，Windows 上是栈溢出异常 0xC00000FD。

void boom(int n) { boom(n + 1); }        // 没有边界条件：帧越压越多，直到栈爆掉
int  deep(int n) { if (n == 0) return 0; return deep(n - 1) + 1; }   // 有边界，但 n 太大照样溢出

另一半陷阱在 static。§4.12.2：自动变量（形参和普通局部变量）在调用开始时分配、调用结束时释放；§4.12.3 与例 4.12：static 局部变量在静态存储区分配，整个程序运行期间都不释放，只赋初值一次，下次调用保留上次的值。于是同一段代码，两种命运：

int f(int n)
{
    static int c = 0;      // 静态局部变量：只初始化一次，地址固定，跨调用保留
    c++;
    if (n > 1) f(n - 1);
    return c;
}
图 CPP-03f · 连调两次 f(3)：auto 版 vs static 版切换模式后调用
选一种模式，再点「调用 f(3)」；连点两次看差别。

教训static 计数器会把递归层的计数搅乱。想在递归里统计「本层是第几层」，用 static int depth 是错的——它是全递归共享的一个格子，不是每层一份；该用形参往下传（本页所有动画里的深度都是这么来的）。反过来，例 4.12 那种「想跨调用保留值」的需求，才该用 static。

压不爆的替代递归深度不可控时，两条路：改成循环（阶乘、递推天然适合）；尾递归——return f(n-1) * n 不是尾调用（返回前还有乘法），改写不成；而尾递归形式的函数在开启优化后常被编译器改成循环，不占新帧。调试手段：ulimit -s 看栈限制，gdb 里 bt 看栈回溯，或在函数入口加深度断言。
